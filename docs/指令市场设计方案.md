基于您已有的 **Supabase** 后端，我将为您设计一套完整的**指令与指令市场**系统方案。Supabase 提供了开箱即用的 PostgreSQL 数据库、认证、存储和 API，可以大大简化开发。我们将充分利用这些能力，实现一个灵活、可扩展的指令体系，让客户端能够动态加载指令并执行确定性任务（如纠错、翻译），同时每个指令可自带数据维护入口（如术语管理）。

## 二、Supabase 集成要点

### 2.1 认证
- 使用 Supabase Auth 管理用户登录/注册。
- 客户端通过 `@supabase/supabase-js` 进行身份验证，获取 JWT。
- 后续所有对 Supabase 的请求都会自动附加 token，RLS 策略基于该 token 控制权限。

### 2.2 数据库
- 使用 Supabase 提供的 PostgreSQL 数据库。
- 定义 `commands`、`terms` 等表，并启用 RLS。
- 客户端直接使用 Supabase JavaScript 客户端库查询和修改数据（需确保权限正确）。

### 2.3 存储
- 用于存储指令图标等静态资源。
- 创建 `command-icons` 存储桶，设置公开读取或私有（根据需求）。
- 客户端通过 Supabase 客户端获取文件的公共 URL。

### 2.4 边缘函数（可选）
- 用于处理一些需要后端逻辑的操作，如指令下载计数、复杂权限校验等。
- 也可直接使用数据库函数 + RLS 实现。

## 三、数据库表设计

### 3.1 用户表
Supabase 已内置 `auth.users`，我们无需创建，但可以通过关联表存储额外信息（如角色）。建议在 `public` 模式下创建 `profiles` 表与 `auth.users` 关联。

```sql
-- 用户档案表，扩展 auth.users
create table public.profiles (
  id uuid references auth.users on delete cascade primary key,
  username text unique,
  role text default 'user' check (role in ('user', 'admin')),
  created_at timestamptz default now()
);

-- 自动创建档案的触发器（可选）
```

### 3.2 指令表 `commands`
存储所有指令的元数据和配置。

```sql
create table public.commands (
  id uuid default gen_random_uuid() primary key,
  name text not null unique,                 -- 指令名称，如“文档纠错”
  version text not null,                      -- 语义化版本，如 "1.0.0"
  description text,                           -- 简短描述
  icon_path text,                             -- 存储中的图标路径（如 command-icons/doc-corrector.svg）
  author text,                                 -- 作者
  homepage text,                               -- 项目主页（可选）
  config jsonb not null,                       -- 完整指令配置（符合下文 schema）
  is_published boolean default true,           -- 是否上架市场
  download_count integer default 0,            -- 下载次数（可后续通过边缘函数更新）
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 启用 RLS
alter table public.commands enable row level security;

-- 策略：
-- 所有人可查看已发布的指令
create policy "Anyone can view published commands"
  on public.commands for select
  using (is_published = true);

-- 只有管理员可以插入/更新/删除
create policy "Admins can insert"
  on public.commands for insert
  with check (auth.uid() in (select id from public.profiles where role = 'admin'));

create policy "Admins can update"
  on public.commands for update
  using (auth.uid() in (select id from public.profiles where role = 'admin'));

create policy "Admins can delete"
  on public.commands for delete
  using (auth.uid() in (select id from public.profiles where role = 'admin'));
```

### 3.3 术语表 `terms`
（如果您需要为纠错指令维护术语，可放在此表中）

```sql
create table public.terms (
  id uuid default gen_random_uuid() primary key,
  incorrect_pattern text not null,
  correct_text text not null,
  description text,
  priority integer default 0,
  created_by uuid references public.profiles(id),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 启用 RLS
alter table public.terms enable row level security;

-- 策略示例：所有登录用户可读，仅管理员可写
create policy "Users can read terms"
  on public.terms for select
  using (auth.role() = 'authenticated');

create policy "Admins can write terms"
  on public.terms for all
  using (auth.uid() in (select id from public.profiles where role = 'admin'));
```

### 3.4 用户指令安装表 `user_commands`（可选，用于记录用户已安装的指令及版本）
如果需要跟踪每个用户安装了哪些指令、版本，可以创建此表。

```sql
create table public.user_commands (
  user_id uuid references public.profiles(id) on delete cascade,
  command_id uuid references public.commands(id) on delete cascade,
  installed_version text not null,
  installed_at timestamptz default now(),
  primary key (user_id, command_id)
);
```

## 四、指令配置格式 (JSON Schema)

指令的核心是一个 JSON 对象，存储在 `commands.config` 字段中。它定义了指令界面和交互行为。

```json
{
  "$schema": "https://your-server/command-schema.json",
  "displayName": "文档纠错",                // 界面显示名称（可选，默认用 name）
  "prompt": "你是一个文档纠错助手，严格按照术语表进行纠正……", // 提示词，可显示在界面顶部
  "inputPlaceholder": "请输入需要纠错的文本...",
  "showResult": true,
  "buttons": [
    {
      "label": "开始纠错",
      "action": "call-api",
      "api": {
        "url": "/api/correct",              // 相对路径，客户端自动拼接 Supabase URL
        "method": "POST",
        "body": { "text": "{{input}}" },    // {{input}} 会被替换为用户输入
        "resultPath": "corrected_text"       // 从返回JSON中提取要展示的字段
      }
    },
    {
      "label": "管理术语表",
      "action": "open-url",
      "url": "/admin/terms"                  // 相对路径，自动拼接 Supabase URL
    },
    {
      "label": "查看帮助",
      "action": "open-url",
      "url": "https://internal-wiki/commands/doc-corrector"
    }
  ]
}
```

**说明**：
- `action` 支持两种：`call-api` 和 `open-url`。
- `call-api` 的 `url` 可以是相对路径，客户端会拼接 Supabase 的 API 基础 URL（如 `https://your-project.supabase.co/rest/v1/rpc/custom_function` 或自定义函数路径）。建议使用 Supabase 的 **Edge Functions** 或 **Database Functions** 来提供业务 API，这样可以获得更灵活的逻辑。
- `{{input}}` 替换：客户端将用户输入的内容替换掉该占位符后发送请求。
- `resultPath`：支持点号路径，如 `data.result`，从响应 JSON 中提取指定字段显示在结果区域。
- `open-url` 的 URL 也可以是相对路径，客户端自动拼接 Supabase 项目 URL（如 `https://your-project.supabase.co`），并可附加 token 参数以实现自动登录（需服务器端处理 token 验证）。

## 五、客户端功能详细拆解

### 5.1 认证模块
- **技术**：使用 `@supabase/supabase-js`。
- **步骤**：
  1. 初始化 Supabase 客户端：`createClient(SUPABASE_URL, SUPABASE_ANON_KEY)`。
  2. 提供登录界面（邮箱+密码，或 magic link 等）。
  3. 登录成功后，Supabase 客户端自动存储 session，后续请求自动携带 token。
  4. 获取当前用户信息：`supabase.auth.getUser()`。
  5. 登出：`supabase.auth.signOut()`。
- **预期结果**：用户登录后，可以访问需要认证的 API 和数据库。

### 5.2 指令市场界面

#### 5.2.1 获取指令列表
- 调用 `supabase.from('commands').select('id,name,version,description,icon_path,author,download_count').eq('is_published', true)`。
- 如果需要按分类或搜索，可添加过滤条件。
- **预期结果**：返回所有已发布指令的基本信息列表。

#### 5.2.2 展示指令卡片
- 每个卡片显示：图标（从 Storage 加载）、名称、版本、描述、作者、下载次数。
- 图标加载：若 `icon_path` 存在，使用 `supabase.storage.from('command-icons').getPublicUrl(icon_path)` 获取公开 URL 并显示；否则显示默认图标。

#### 5.2.3 判断本地安装状态
- 客户端本地维护一个已安装指令的目录（例如 `commands/`），存储下载的 JSON 文件。文件名建议使用 `name` 或 `id`。
- 加载本地所有指令文件，提取 `name` 和 `version`，与服务器列表对比，标记每个指令的状态：未安装、可更新、已安装。

#### 5.2.4 安装/更新指令
- **安装**：点击“安装”按钮，调用 `supabase.from('commands').select('config').eq('id', commandId).single()` 获取完整配置。然后将指令元数据（包括 `name`, `version`, `config` 等）保存为本地 JSON 文件，例如 `commands/文档纠错.json`。同时更新 `user_commands` 表（可选）。
- **更新**：类似安装，但会覆盖本地文件，并更新 `user_commands` 中的版本。
- **预期结果**：本地 `commands/` 目录下出现对应指令的 JSON 文件，之后用户可在“我的指令”中看到。

#### 5.2.5 下载计数（可选）
- 可在边缘函数中实现：每次下载时调用一个边缘函数，原子性地增加 `download_count`。或者使用数据库函数和 RLS 直接更新（需注意权限）。
- **简单方案**：每次客户端下载指令时，调用一个自定义 RPC：
  ```sql
  create or replace function increment_command_download(command_id uuid)
  returns void as $$
  begin
    update public.commands set download_count = download_count + 1 where id = command_id;
  end;
  $$ language plpgsql security definer;
  ```
  客户端：`supabase.rpc('increment_command_download', { command_id })`。

### 5.3 指令详情界面

#### 5.3.1 打开指令
- 用户从“我的指令”列表点击某个指令，打开新窗口或右侧面板。
- 加载对应的本地 JSON 文件，解析 `config`。

#### 5.3.2 动态渲染界面
- 根据 `config` 渲染：
  - 顶部显示指令名称和描述。
  - 如果存在 `prompt`，显示一个信息框（可折叠）。
  - 如果存在 `inputPlaceholder`，渲染一个多行输入框。
  - 根据 `buttons` 数组渲染按钮（水平排列）。
  - 如果 `showResult` 为 true，渲染一个只读的文本区域用于显示结果。
- **预期结果**：界面完全由 JSON 配置驱动，无需硬编码。

#### 5.3.3 按钮点击处理
- **`open-url`**：
  - 使用 Electron 的 `shell.openExternal(url)` 在默认浏览器中打开。
  - 如果 URL 是相对路径（如 `/admin/terms`），则拼接 Supabase 项目 URL：`https://your-project.supabase.co/admin/terms`。
  - 为了保持登录状态，可以在 URL 后附加 token 参数：`?access_token=...`。服务器端需要解析 token 并建立会话（例如通过 Supabase Auth 的 `getUser(token)`）。注意安全：内网环境可接受。
- **`call-api`**：
  1. 获取用户输入内容（如果有）。
  2. 将 `api.body` 中的 `{{input}}` 替换为用户输入。
  3. 从 Supabase 客户端获取当前会话的 token：`supabase.auth.session()?.access_token`。
  4. 使用 `fetch` 或 `axios` 调用 API：
     - 如果 `api.url` 是相对路径，拼接 Supabase 的 API URL（例如 `https://your-project.supabase.co` + url）。
     - 添加请求头：`Authorization: Bearer <token>`，`Content-Type: application/json`。
  5. 收到响应后，根据 `resultPath` 提取要显示的文本，更新结果区域。
  6. 错误处理：显示友好错误信息。

#### 5.3.4 高级：内嵌 Web 视图
- 如果未来需要更复杂的界面，可在指令配置中增加 `embedUrl` 字段，客户端内嵌一个 `BrowserView` 加载该 URL，并通过 `postMessage` 与主进程通信（如传递用户输入、接收结果）。此部分可作为扩展选项。

### 5.4 术语管理入口
- 在指令配置的 `buttons` 中添加一个 `open-url` 按钮，URL 指向服务器上的术语管理页面（如 `/admin/terms`）。
- 服务器端需要提供该页面（可使用 Supabase 的 Studio 或自行开发 Vue/React 应用并部署为静态页面）。
- 为保证认证，可在 URL 中附加 token 参数，服务器端验证 token 后显示页面。

## 六、服务器端（Supabase）功能实现细节

### 6.1 指令管理后台
- 可以直接使用 Supabase 的 **Studio**（内置表格编辑器）来管理 `commands` 表，管理员可以手动插入/更新 JSON 配置和图标。但为了更好的体验，建议开发一个简单管理界面：
  - 使用 Vue/React，通过 Supabase 客户端操作 `commands` 表。
  - 提供表单编辑 JSON 配置，上传图标到 Storage。
  - 限制仅管理员可访问（通过 RLS 和前端路由控制）。
- **步骤**：
  1. 创建管理界面路由 `/admin/commands`。
  2. 登录用户检测 `role`，非管理员重定向。
  3. 实现指令列表、新增、编辑、删除。
  4. 编辑时，提供 JSON 编辑器（如 monaco-editor）并校验格式。
  5. 图标上传：调用 `supabase.storage.from('command-icons').upload(file)`，获取路径存入 `icon_path`。

### 6.2 业务 API（如纠错）
- 对于需要后端处理的 API（如 `/api/correct`），有两种实现方式：
  - **Supabase Edge Functions**：编写 TypeScript 函数，部署为独立 API。适合需要复杂逻辑或调用外部大模型的场景。
  - **PostgreSQL 函数 + HTTP API**：使用 Supabase 的自动 REST API 或自定义 RPC。适合纯数据库操作。
- **推荐**：使用 Edge Functions，因为它更灵活，可以调用外部服务（如大模型）。Edge Function 可通过 Supabase 客户端调用，URL 为 `https://your-project.supabase.co/functions/v1/correct`。
- **Edge Function 示例**（纠错）：
  ```typescript
  import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
  import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

  serve(async (req) => {
    const { text } = await req.json()
    const supabase = createClient(
      Deno.env.get('SUPABASE_URL')!,
      Deno.env.get('SUPABASE_ANON_KEY')!,
      { global: { headers: { Authorization: req.headers.get('Authorization')! } } }
    )

    // 从数据库获取术语表
    const { data: terms } = await supabase.from('terms').select('incorrect_pattern, correct_text')
    // 执行规则引擎替换
    let corrected = text
    for (const term of terms) {
      const regex = new RegExp(term.incorrect_pattern, 'g')
      corrected = corrected.replace(regex, term.correct_text)
    }

    // 可选调用大模型
    // ...

    return new Response(JSON.stringify({ corrected_text: corrected }), {
      headers: { 'Content-Type': 'application/json' }
    })
  })
  ```

### 6.3 术语管理页面
- 开发一个单页应用，部署为 Supabase Storage 中的静态网站，或使用 Supabase 的 Hosting 功能。
- 使用 Supabase 客户端与 `terms` 表交互，同样依赖 RLS 权限。
- 页面路径示例：`/admin/terms`。
- 登录处理：若访问时未登录，重定向到登录页；登录后返回原页。可以利用 Supabase Auth 的 `onAuthStateChange`。

## 七、详细实施步骤清单

以下是从零开始到完成功能的分步指南，每一步都有明确输入和输出。

### 阶段一：Supabase 项目准备
1. **创建 Supabase 项目**，记录项目 URL 和 anon key。
2. **启用邮箱认证**（或根据需要配置其他认证方式）。
3. **创建存储桶** `command-icons`，设置为公开（或私有，但需要签名 URL）。
4. **创建数据库表**（按上面 SQL 执行）：
   - `profiles` 表及触发器。
   - `commands` 表及 RLS。
   - `terms` 表及 RLS（可选）。
   - `user_commands` 表（可选）。
5. **创建管理员用户**：通过 Supabase Auth 添加一个用户，然后在 `profiles` 中手动设置 role='admin'。

### 阶段二：客户端基础改造
1. **安装 Supabase 客户端**：`npm install @supabase/supabase-js`。
2. **初始化 Supabase 客户端**：在 Electron 主进程或渲染进程中创建单例。
3. **添加登录界面**：
   - 使用 Supabase Auth 的 `signInWithPassword` 或 `signInWithOtp`。
   - 成功后，存储 session。
4. **获取当前用户信息**，显示用户名和角色。
5. **创建本地指令目录**：在用户数据目录下创建 `commands` 文件夹（可通过 `app.getPath('userData')` 获取路径）。

### 阶段三：指令市场界面开发
1. **创建市场页面组件**（如 `CommandMarket.tsx`）。
2. **获取指令列表**：
   ```ts
   const { data: commands } = await supabase
     .from('commands')
     .select('id, name, version, description, icon_path, author, download_count')
     .eq('is_published', true);
   ```
3. **读取本地已安装指令**：
   - 使用 Node.js `fs` 模块（通过 Electron 的 IPC）读取 `commands` 目录下所有 `.json` 文件，解析出 `name` 和 `version`。
   - 渲染时，比对 `commands` 列表，为每个指令添加状态。
4. **实现安装/更新功能**：
   - 创建 IPC 处理程序 `install-command`，接收 `commandId`。
   - 在 IPC 处理程序中，从 Supabase 获取完整配置：`supabase.from('commands').select('config, name, version').eq('id', id).single()`。
   - 将数据写入本地文件：`fs.writeFileSync(path.join(commandsDir, `${name}.json`), JSON.stringify(data, null, 2))`。
   - 可选：调用 `supabase.rpc('increment_command_download', { command_id: id })` 更新下载计数。
   - 返回成功状态给渲染进程，更新 UI。
5. **图标加载**：在卡片中，使用 `supabase.storage.from('command-icons').getPublicUrl(icon_path).data.publicUrl`。

### 阶段四：指令详情界面开发
1. **创建指令详情组件**（如 `CommandDetail.tsx`），接收指令名称作为参数。
2. **加载本地 JSON**：通过 IPC 读取对应文件内容。
3. **动态渲染 UI**：
   - 使用 React 状态存储用户输入。
   - 根据 `config.buttons` 循环渲染按钮。
   - 根据 `config.inputPlaceholder` 渲染 `<textarea>`。
   - 根据 `config.showResult` 渲染结果区域。
4. **实现按钮点击处理函数**：
   - 对于 `open-url`：使用 Electron 的 `shell.openExternal(url)`。
   - 对于 `call-api`：
     - 获取当前 token：`supabase.auth.session()?.access_token`。
     - 拼接完整 URL（如果相对路径则加上 Supabase URL）。
     - 替换 body 中的 `{{input}}`。
     - 发起 fetch 请求，带上 token。
     - 根据 `resultPath` 提取结果（可使用 lodash.get 或自己实现），更新结果状态。
5. **错误处理**：显示错误信息在结果区域。

## 八、注意事项与最佳实践

- **安全性**：
  - 所有客户端对 Supabase 的请求都通过 anon key + JWT 进行，RLS 确保数据安全。
  - 边缘函数中需要验证 token（Supabase 客户端会自动处理，但手动 fetch 时需校验）。
  - 打开的 URL 应限制为内网地址，避免被恶意指令跳转到外部。可在客户端配置允许的域名白名单。
- **离线支持**：
  - 指令下载后存储在本地，即使断网，用户仍可使用已安装指令（但调用 API 会失败）。
  - 市场页面需要网络才能获取最新指令列表。
- **版本管理**：
  - 指令版本更新时，客户端应检测并提示用户更新。可通过比较本地版本和服务器版本实现。
- **性能**：
  - 指令列表可缓存，减少请求。
  - 边缘函数应优化，避免每次查询术语表都扫描全表（可加入 Redis 缓存，但 Supabase 无内置 Redis，可考虑使用数据库函数缓存）。
- **扩展性**：
  - 未来可增加指令分类、评分、评论等，只需在 `commands` 表加字段。
  - 指令可依赖其他指令（如术语管理指令可被纠错指令调用），但初期先保持简单。

通过以上设计，您实现了：

1. **动态加载指令**：客户端无需修改代码，只需从 Supabase 下载 JSON 配置即可获得新功能。
