# 01 - 通用文件读取方案（Universal File Reader）

> 创建日期：2026-06-12 | 更新日期：2026-06-13
> 状态：**待确认**
> OCR 服务已确认为 **MinerU**（`POST /file_parse`，multipart/form-data）

## 1. 背景与目标

### 现状分析

当前 `read_file` 工具（`electron/main/tools/FileTools.ts`）存在以下限制：

| 限制 | 详情 |
|------|------|
| **纯文本读取** | 仅支持逐行文本读取，遇到二进制文件直接拒绝 |
| **Office 文件被列为二进制** | `.doc/.docx/.xls/.xlsx/.ppt/.pptx` 均在 `BINARY_EXTENSIONS` 中被排除 |
| **PDF 被列为二进制** | `.pdf` 无法读取 |
| **无 OCR 能力** | 扫描件 PDF、图片中的文字无法提取 |
| **无图片理解** | 文档中的图片仅作为二进制被跳过 |

### 目标

将 `read_file` 改造为**通用文档读取器**，支持：

```
read_file("报告.docx")  → 返回文本 + 图片引用
read_file("数据.xlsx")  → 返回结构化表格数据
read_file("扫描件.pdf") → OCR 识别文本 + 图片引用
read_file("截图.png")   → 图片描述（调用多模态模型）
read_file("手册.md")    → 纯文本（现有能力）
```

## 2. 架构设计

### 2.1 分层架构

```
┌─────────────────────────────────────────────────┐
│                  read_file 工具                   │
│            (统一入口，自动检测文件类型)              │
├─────────────────────────────────────────────────┤
│               FileReaderRouter                    │
│          根据文件扩展名路由到对应 Reader             │
├──────┬──────┬──────┬──────┬──────┬──────┬────────┤
│Text  │Word  │Excel │PPT   │PDF   │Image │Other   │
│Reader│Reader│Reader│Reader│Reader│Reader│Reader  │
├──────┴──────┴──────┴──────┴──────┴──────┴────────┤
│              External Service Adapter             │
│    ┌────────────────┐    ┌──────────────────┐    │
│    │  本地 OCR 服务   │    │  多模态 LLM API  │    │
│    │  (文本识别)      │    │  (图片理解)      │    │
│    └────────────────┘    └──────────────────┘    │

```

### 2.2 文件类型路由规则

```typescript
interface FileReaderRoute {
  extensions: string[];
  reader: string;           // reader 标识名
  requiresExternal: boolean; // 是否需要外部服务
  fallbackToBinary: boolean; // 外部服务不可用时是否回退为二进制提示
}

const FILE_ROUTES: FileReaderRoute[] = [
  { extensions: ['.txt', '.md', '.csv', '.json', '.xml', '.yaml', '.yml', '.log', '.ini', '.conf', '.sh', '.bat', '.py', '.js', '.ts'],
    reader: 'text', requiresExternal: false, fallbackToBinary: false },
  { extensions: ['.doc', '.docx'],
    reader: 'word', requiresExternal: true, fallbackToBinary: true },
  { extensions: ['.xls', '.xlsx', '.xlsm'],
    reader: 'excel', requiresExternal: true, fallbackToBinary: true },
  { extensions: ['.ppt', '.pptx'],
    reader: 'ppt', requiresExternal: true, fallbackToBinary: true },
  { extensions: ['.pdf'],
    reader: 'pdf', requiresExternal: true, fallbackToBinary: true },
  { extensions: ['.png', '.jpg', '.jpeg', '.bmp', '.tiff', '.webp'],
    reader: 'image', requiresExternal: true, fallbackToBinary: true },
];
```

### 2.3 各 Reader 的实现策略

#### TextReader（纯文本）

**保持现有逻辑不变**，直接逐行读取。无需外部服务。

#### WordReader（.doc/.docx）

**方案 A：本地解析（推荐优先）**
- 利用已有的内嵌 Python + `python-docx` 库
- 调用方式：通过 bash 工具执行 Python 脚本
- 提取内容：文本段落 + 表格数据 + 图片（保存为临时文件）

**方案 B：使用 officecli-lite**
- 利用已有的 `.config/bin/officecli.exe`
- 调用 `officecli view docx` 获取文档结构

**方案 C：外部 OCR 服务（仅用于扫描件 Word）**
- 如果文档中包含扫描图片，提取图片后调用 OCR 服务

#### ExcelReader（.xls/.xlsx）

**方案：内嵌 Python + openpyxl**
- 利用已有的 `openpyxl` 库（已安装在嵌入 Python 中）
- 返回格式：Markdown 表格
- 大文件处理：分 Sheet 读取，单个 Sheet 限制行数

```python
# 示例输出格式
## Sheet1

| A | B | C |
|---|---|---|
| 姓名 | 年龄 | 部门 |
| 张三 | 28 | 技术部 |
```

#### PDFReader（.pdf）

**分情况处理**：

| PDF 类型 | 检测方式 | 处理策略 |
|----------|----------|----------|
| 文本型 PDF | `pypdf` 提取文本 > 阈值 | 直接提取文本 |
| 扫描型 PDF | `pypdf` 提取文本 < 阈值 | 调用 OCR 服务 |
| 混合型 PDF | 部分页有文本，部分无 | 文本页直接提取 + 扫描页 OCR |

**OCR 服务接口设计**：

```typescript
interface OCRServiceConfig {
  /** OCR 服务地址 */
  endpoint: string;
  /** 支持的识别类型 */
  capabilities: ('text' | 'table' | 'formula')[];
  /** 超时时间(ms) */
  timeout: number;
}

// 调用示例
const result = await ocrService.recognize(pdfPageImage, {
  type: 'text',
  language: 'chi_sim+eng'
});
```

OCR 服务为 **MinerU**（已部署在内网）：
- 接口：`POST http://{host}:{port}/file_parse`
- 格式：multipart/form-data，上传文件
- 支持格式：PDF、JPG、PNG（扩展名必须小写）
- 关键参数：`parse_method`(auto/ocr/txt)、`return_md`(true)、`return_images`(true)
- 返回：JSON（含 Markdown 文本、图片列表）
- 不支持 URL/Base64 输入，必须上传文件

#### ImageReader（图片）

**方案：调用多模态 LLM**
- 将图片转为 Base64
- 通过 OpenAI 兼容的 Vision API 发送
- 返回图片的文字描述

```typescript
interface ImageReadResult {
  text: string;          // 图片中的文字（如果有）
  description: string;   // AI 生成的图片描述
  imageRef?: string;     // 图片引用标识，供后续引用
}
```

### 3.3 图片引用机制

当文档包含图片时，`read_file` 会：

1. 将图片提取到临时目录（`.config/data/tmp/images/`）
2. 在文本内容中插入图片占位标记：`[图片: img_001]`
3. AI 可以在回复中引用图片：
   - 向用户描述图片内容
   - 通过 `image_ref` 参数在后续操作中使用图片

```
AI 回复示例：
"根据运维手册第3章，当服务器掉线时应按以下步骤处理：

1. 首先检查网络连接状态（见下方图片）

[引用图片: img_001 - 网络拓扑图]

2. 如果是网关问题，执行 `ping 192.168.1.1` 测试连通性..."
```

## 4. 外部 OCR 服务集成（MinerU）

### 4.1 服务配置

在 `.config/config.json` 中新增 MinerU 配置：

```json
{
  "mineru": {
    "enabled": true,
    "endpoint": "http://192.168.1.100:8900",
    "timeout": 60000,
    "parseMethod": "auto",
    "returnImages": true,
    "formulaEnable": true,
    "tableEnable": true
  }
}
```

### 4.2 MinerU API 规格

```
POST /file_parse
Content-Type: multipart/form-data

参数：
  files             必填    上传文件（PDF/JPG/PNG）
  backend           可选    "pipeline"（默认，推荐本地部署）
  parse_method      可选    "auto" | "ocr" | "txt"
  return_md         可选    true（默认，返回 Markdown）
  return_images     可选    false（是否返回提取的图片）
  formula_enable    可选    true（公式识别）
  table_enable      可选    true（表格识别）
  start_page_id     可选    0（起始页）
  end_page_id       可选    99999（结束页）
  lang_list         可选    ["ch"]

调用示例：
curl -X POST http://host:8900/file_parse \
  -F "files=@/path/to/doc.pdf" \
  -F "return_md=true" \
  -F "return_images=true"

注意事项：
  - 文件扩展名必须小写（.pdf, .jpg）
  - 不支持 URL/Base64，必须上传文件
  - backend 只能传单个字符串
```

### 4.3 MinerU 适配器接口

```typescript
interface OCRAdapter {
  /** 识别图片中的文字 */
  recognize(image: Buffer | string, options?: OCROptions): Promise<OCRResult>;
  /** 识别 PDF 文件 */
  recognizePDF(pdfPath: string, options?: OCROptions): Promise<OCRResult[]>;
}

interface OCROptions {
  language?: string;
  pages?: string;  // 页码范围
  includeImages?: boolean;
}

interface OCRResult {
  text: string;
  confidence: number;
  page?: number;
  images?: Array<{ ref: string; bbox: [number, number, number, number] }>;
}
```

### 4.4 内置 fallback 策略

当 MinerU 服务不可用时：

| 场景 | 策略 |
|------|------|
| 文本型 PDF | `pypdf` 直接提取（不依赖 MinerU） |
| Word/Excel | `python-docx` / `openpyxl` 直接解析 |
| 扫描型 PDF | 返回提示："该文档为扫描件，需要 MinerU 服务支持。请配置 MinerU 服务后重试。" |
| 图片 | 尝试调用多模态 LLM 描述，或返回 "需要 MinerU 服务" |

## 5. 性能与安全考量

### 性能

| 场景 | 预估耗时 | 优化策略 |
|------|----------|----------|
| 文本文件 | <100ms | 保持现有逻辑 |
| Word (10页) | 1-3s | Python 进程池复用 |
| Excel (1000行) | <1s | 分 Sheet 懒加载 |
| PDF (10页文本) | 1-2s | pypdf 流式读取 |
| PDF (10页扫描) | 5-30s | 取决于 OCR 服务 |

### 安全

- **文件大小限制**：文档类文件限制 100MB，超过拒绝读取
- **临时文件清理**：提取的图片在 1 小时后自动清理
- **OCR 服务认证**：支持配置 API Key
- **输入校验**：路径遍历检查（现有逻辑已覆盖）
