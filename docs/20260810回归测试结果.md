## 三、新发现的问题

### 3.1 ❌【新回归 bug】get 单元格 text 返回空

```
get /table[2]/row[1]/cell[1] text → ""（应为"姓名"）
```

**根因**：`Gt()` 函数只拼接**直接子元素** `w:r` 的文本：
```js
function Gt(s){let e="";for(let t of b(s,"w:r"))for(let n of b(t,"w:t"))e+=ze(n);return e}
// b() 只取直接子节点：
function b(s,e){return s.children.filter(t=>t.type==="element"&&t.tag===e)}
```
修复 P0 后单元格结构变为 `w:tc > w:p > w:r > w:t`，run 不再是 tc 的**直接子节点**，所以 `Gt(tc)` 读不到文本。**上次能读到是因为游离 run 恰好是 tc 直接子节点**——现在结构合法了，get 反而读不到，属于"修复 P0 时引入的回归"。

**影响**：`view`（走 cells 逻辑）正常、`find` 正常、python-docx 正常，**只有 `get cell text` 单个接口受影响**，可用 `get /table[n] cells` 替代。

**建议修复**：`Gt()` 改为递归查找 `w:t`（或对 `w:tc` 先取 `w:p` 再取 run）：
```js
function Gt(s){let e="";for(let t of s.findall('.//w:t'))e+=...;return e}
```

### 3.2 ❌【仍未修复】add paragraph 到 cell 无效

```
add /table[2]/row[1]/cell[1] paragraph → Added paragraph（提示成功）
```
实际 XML：新增 `<w:p/>` 被加到了**表格外 body 末尾**（`</w:tbl><w:p></w:p>`），不是加进 cell。与上次报告 2.13 完全一致。
**根因**：`add` 的 paragraph 分支用 `Zt(u,E,A)`（在父级插入），`Nt()` 定位到 cell 后，`Zt` 在 cell 的父容器（body/tr 层）操作，未正确处理"插入到 cell 内部"的场景。**单元格内多段落能力仍不可用。**

### 3.3 ⚠️ office_add 工具层不透传 rows/cols

CLI 支持 `--rows 3 --cols 4`，但 `office_add` 工具调用时固定生成 2x2（参数未映射）。需要用户在 office_add 接口补上行列参数（或直接用 CLI）。

### 3.4 ❌ validate 仍不可用

`office_validate` 返回"文档校验功能在轻量版中暂不可用"，CLI `validate` 命令也不存在（unknown command）。建议补充，或在每次写入后自动做基本结构自检。

## 四、源码层面确认的优化点

1. **`Gt()` 文本提取**：`b(s,"w:r")` 只找直接子元素 → 应递归（上面 3.1）。
2. **`add` paragraph 到 cell**：`Zt()` 的插入逻辑未区分"插到 cell 内部"与"插到同级"（上面 3.2）。
3. **`get /table[n] text`**：整表 text 返回空字符串，虽然已有 `cells` 属性兜底，但建议 `text` 对 `w:tbl` 返回所有单元格文本拼接。
4. **`validate` 缺失**：CLI 命令表中没有 validate。
