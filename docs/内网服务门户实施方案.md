# 零员工内网服务门户实施方案

> 探讨在内网环境下，为「螺丝钉」构建统一服务门户的技术方案。
> 涵盖软件分发、版本升级、Python 包镜像、Skill 市场四大模块。

---

## 一、背景与问题分析

### 1.1 现状

- 「螺丝钉」运行在**内网**环境中，用户终端在**互联网**侧
- 目前缺乏统一入口：软件分发靠手动拷贝，没有版本管理
- 内置 Python 3.8 环境，包安装依赖公网 pip，内网无法使用
- Skill（技能）仅支持本地管理和 P2P 共享，无集中式市场
- 没有自动升级机制，版本更新全靠人工通知

### 1.2 目标

搭建一个**内网可访问的 Web 门户**，作为所有服务的统一入口：

| 模块 | 核心能力 |
|------|---------|
| 软件分发 | 下载页面、功能介绍、安装引导 |
| 版本升级 | 版本管理、增量/全量更新、更新推送 |
| Python 包镜像 | 私有 PyPI 源、包管理、Agent 自动引用 |
| Skill 市场 | 提交/审核/下载/版本管理 |

### 1.3 网络拓扑

```

│                      互联网（用户侧）                         │
```

**关键点**：
- **Supabase** 作为统一后端，提供数据库、认证、存储、边缘函数、实时推送
- Web 门户为独立静态站点，通过 Supabase JS SDK 访问后端
- 客户端（螺丝钉）同样通过 Supabase SDK 直连，无需自建 API 层
- Nginx 统一代理 Web 门户 + Supabase 服务

## 二、技术选型

基于内网已部署的 **Supabase** 实例，最大化利用其内置能力：

| 层级 | 技术方案 | 说明 |
|------|---------|------|
| Web 前端 | **Vue 3 + Vite**（静态站点） | 轻量、构建快、易部署 |
| 后端服务 | **Supabase**（已部署） | PostgreSQL + Auth + Storage + Edge Functions + Realtime |
| 数据库 | **Supabase PostgreSQL** | 内置 RLS 行级安全，自动生成 REST API |
| 认证 | **Supabase Auth** | 邮箱/密码登录，JWT 鉴权 |
| 文件存储 | **Supabase Storage** | 安装包、Skill 包、Python 包统一管理 |
| 边缘函数 | **Supabase Edge Functions** | PyPI Simple API、下载计数、版本比较等定制逻辑 |
| 客户端 SDK | **@supabase/supabase-js** | 客户端直连 Supabase，无需自建 API 网关 |
| 反向代理 | **Nginx** | 统一入口，HTTPS 终结 |

**架构优势**：
- **零后端开发**：大部分 API 由 Supabase 自动生成，只需建表 + 配置 RLS
- **统一认证**：Web 门户和客户端共用同一套用户体系
- **实时能力**：利用 Supabase Realtime 可实现版本更新推送、Skill 市场通知
- **运维简单**：只需维护 Supabase + Nginx + 静态站点，无需额外后端服务

## 三、模块一：Web 门户与软件分发

### 3.1 功能清单

```
门户首页
├── 首页 ──── 产品介绍、核心功能展示、快速下载入口
├── 下载页 ── 历史版本列表、系统要求、安装指南
├── 功能页 ── 各模块详细介绍（对话、工具、技能等）
├── 文档页 ── 使用手册、API 文档、常见问题
└── 管理后台 ── 管理员专用（版本发布、用户管理、数据统计）
```

### 3.2 页面设计要点

**首页**：展示产品定位和核心卖点
- 英雄区：产品名称 + 一句话描述 + 下载按钮
- 功能卡片：3-4 个核心功能展示
- 版本动态：最新版本号和更新日志摘要
- 系统要求：支持的操作系统、硬件配置

**下载页**：
- 默认推荐最新稳定版
- 历史版本列表（版本号 + 发布日期 + 变更摘要）
- 校验信息（SHA256 哈希值）
- 安装指南（Windows 步骤说明）

### 3.3 Supabase 集成方式

Web 门户和客户端统一使用 `@supabase/supabase-js` 直连 Supabase：

```
# 获取版本列表（自动生成的 REST API）
GET /rest/v1/releases?is_published=eq.true&order=created_at.desc

# 获取最新版本
GET /rest/v1/releases?is_published=eq.true&channel=eq.stable&order=created_at.desc&limit=1

# 下载安装包
GET /storage/v1/object/release-files/{file_path}
```

下载计数通过 **Edge Function** 原子性递增：

```sql
-- RPC：递增下载计数
CREATE OR REPLACE FUNCTION increment_download(release_id INT)
RETURNS void AS $$
  UPDATE releases SET download_count = download_count + 1 WHERE id = release_id;
$$ LANGUAGE sql SECURITY DEFINER;
```

客户端调用：`supabase.rpc('increment_download', { release_id: 15 })`

### 3.4 数据库设计

```sql
-- 版本发布表
CREATE TABLE releases (
  id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  version       VARCHAR(32) NOT NULL UNIQUE,
  channel       VARCHAR(16) DEFAULT 'stable',
  title         VARCHAR(256),
  changelog     TEXT,
  storage_path  VARCHAR(512) NOT NULL,      -- Supabase Storage 中的文件路径
  file_size     BIGINT,
  file_hash     VARCHAR(128),
  min_version   VARCHAR(32),
  is_published  BOOLEAN DEFAULT FALSE,
  download_count INTEGER DEFAULT 0,
  published_at  TIMESTAMPTZ,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- RLS 策略
ALTER TABLE releases ENABLE ROW LEVEL SECURITY;

-- 所有人可查看已发布版本
CREATE POLICY "Published releases are public"
  ON releases FOR SELECT
  USING (is_published = true);

-- 仅管理员可插入/更新/删除
CREATE POLICY "Admins can manage releases"
  ON releases FOR ALL
  USING (auth.jwt() ->> 'role' = 'admin');

-- 创建 Storage 桶
INSERT INTO storage.buckets (id, name, public)
VALUES ('release-files', 'release-files', true);
```

## 四、模块二：版本升级系统

### 4.1 升级流程

```
┌──────────┐    定时/启动时     ┌──────────┐
│ 螺丝钉   │ ────────────────▶ │ 升级 API  │
│ 客户端   │                   │          │
│          │ ◀──────────────── │          │
│          │   版本信息+下载URL  │          │
│          │                   └──────────┘
│          │
│  显示升级  │
│  提示通知  │
│          │
│  用户确认  │
│  下载安装  │ ────────────────▶ 文件存储
│          │ ◀──────────────── 下载完成
│          │
│  执行升级  │
│  重启生效  │
└──────────┘
```

### 4.2 检测策略

客户端通过以下方式检测更新：

1. **启动检测**：应用启动时查询一次
2. **定时检测**：每 4 小时查询一次（可配置）
3. **手动检测**：用户主动点击「检查更新」
4. **实时推送**（可选）：利用 Supabase Realtime 订阅 `releases` 表变更

**Supabase 查询示例**：

```typescript
// 客户端检查更新
const { data } = await supabase
  .from('releases')
  .select('id, version, title, changelog, storage_path, file_size, file_hash, min_version')
  .eq('is_published', true)
  .eq('channel', 'stable')
  .order('created_at', { ascending: false })
  .limit(1)
  .single()

// 比较版本号（客户端本地判断）
if (semver.gt(data.version, currentVersion)) {
  // 有更新
}

// 下载链接从 Storage 获取
const { data: url } = supabase.storage
  .from('release-files')
  .getPublicUrl(data.storage_path)
```

**实时推送**（可选增强）：

```typescript
// 订阅新版本发布事件
supabase.channel('release-updates')
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'releases',
    filter: 'is_published=eq.true'
  }, (payload) => {
    // 通知用户有新版本
    notifyUpdate(payload.new)
  })
  .subscribe()
```

### 4.3 升级方式

考虑到内网环境和当前打包方式（`dir` 目录），推荐两种方案：

| 方案 | 描述 | 适用场景 |
|------|------|---------|
| **全量覆盖** | 下载完整安装包，替换整个应用目录 | 当前首选，实现简单 |
| **增量更新** | 下载差分包，只替换变更文件 | 未来优化，减少下载量 |

**全量覆盖流程**（推荐先实现）：

```
1. 客户端下载新版本 ZIP 包到临时目录
2. 校验 SHA256 哈希值
3. 解压到临时目录
4. 停止所有运行中的任务
5. 将 .config 用户数据备份
6. 用新文件覆盖旧文件
7. 恢复 .config 用户数据
8. 重启应用
```

### 4.4 Supabase Edge Function（版本比较逻辑）

对于复杂的版本比较逻辑，可使用 Edge Function：

```typescript
// supabase/functions/check-update/index.ts
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

serve(async (req) => {
  const { current_version, channel } = await req.json()
  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_ANON_KEY')!
  )

  const { data: latest } = await supabase
    .from('releases')
    .select('*')
    .eq('is_published', true)
    .eq('channel', channel || 'stable')
    .order('created_at', { ascending: false })
    .limit(1)
    .single()

  // 简单版本比较
  const hasUpdate = compareVersions(latest.version, current_version) > 0

  return new Response(JSON.stringify({
    has_update: hasUpdate,
    latest: hasUpdate ? {
      version: latest.version,
      title: latest.title,
      changelog: latest.changelog,
      file_url: supabase.storage.from('release-files').getPublicUrl(latest.storage_path).data.publicUrl,
      file_size: latest.file_size,
      file_hash: latest.file_hash,
      min_version: latest.min_version,
    } : null
  }), { headers: { 'Content-Type': 'application/json' } })
})
```

### 4.5 客户端改造要点

在 `electron/main/` 下新增 `UpdateService` 模块，内部使用 Supabase SDK：

```typescript
// electron/main/services/UpdateService.ts（待实现）
import { createClient, SupabaseClient } from '@supabase/supabase-js'

class UpdateService {
  private supabase: SupabaseClient

  constructor(supabaseUrl: string, supabaseKey: string) {
    this.supabase = createClient(supabaseUrl, supabaseKey)
  }

  // 查询更新（方式一：直接查询 releases 表）

  // 查询更新（方式二：调用 Edge Function，含复杂版本比较）
  async checkForUpdateRPC(currentVersion: string): Promise<UpdateInfo | null>

  // 从 Supabase Storage 下载更新包
  async downloadUpdate(storagePath: string, onProgress: (pct: number) => void): Promise<string>
```

- `update:check` — 检查更新
- `update:download` — 下载更新
- `update:apply` — 应用更新
- `update:on-progress` — 下载进度通知（渲染进程→主进程）

## 五、模块三：Python 包镜像服务

### 5.1 问题分析

「螺丝钉」内置两种 Python 运行环境：

| 运行时 | 版本 | 位置 | 包管理 |
|--------|------|------|--------|
| **CPython**（嵌入式） | 3.8.10 | `electron/main/python/` | pip（当前指向公网 PyPI） |
| **Pyodide**（WebAssembly） | 0.29.3 | `public/pyodide-full/` | 离线预加载 |

内网环境下 CPython 的 pip 无法访问公网 PyPI，需要搭建私有包镜像。

### 5.2 方案选择

```
方案对比：

┌─────────────┬──────────────────────┬────────────────────┐
│    方案      │       优点            │      缺点          │
├─────────────┼──────────────────────┼────────────────────┤
│ devpi       │ 完整 PyPI 镜像+缓存  │ 较重，需维护全量    │
│             │ 支持私有包            │ 同步耗带宽          │
├─────────────┼──────────────────────┼────────────────────┤
│ pypiserver  │ 极轻量，按需上传      │ 无自动镜像能力      │
│             │ 部署简单              │ 需手动管理包        │
├─────────────┼──────────────────────┼────────────────────┤
│ 自建简易源  │ 完全可控，可集成到    │ 需自行开发          │
│ (推荐)      │ 门户 API             │                    │
└─────────────┴──────────────────────┴────────────────────┘
```

**推荐方案**：利用 Supabase Edge Function 实现 PEP 503 兼容源 + Supabase Storage 存放包文件，理由：
- 内网只需托管有限的包（办公文档处理相关），不需要完整镜像
- Edge Function 处理 PyPI Simple API 协议，Storage 存放 .whl 文件
- 管理员通过 Web 后台上传包到 Storage，自动在 `pypi_packages` 表中注册
- 全部复用 Supabase 基础设施，无需额外部署服务

### 5.3 私有 PyPI 源设计

#### 5.3.1 Edge Function 实现 PEP 503 Simple API

pip 客户端需要标准 HTML 响应，通过 Edge Function 提供：

```
# Nginx 将 /pypi/ 路由到 Supabase Edge Function
GET /pypi/simple/                  → Edge Function: pypi-index
GET /pypi/simple/<package>/        → Edge Function: pypi-package
GET /pypi/packages/<file>          → Supabase Storage: pypi-files bucket
```

**Edge Function 示例** (`supabase/functions/pypi-package/index.ts`)：

```typescript
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

serve(async (req) => {
  const url = new URL(req.url)
  const packageName = url.pathname.split('/').filter(Boolean).pop()?.toLowerCase()

  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_ANON_KEY')!
  )

  const { data: files } = await supabase
    .from('pypi_packages')
    .select('filename, storage_path')
    .ilike('name', packageName)
    .order('upload_at', { ascending: false })

  const links = files.map(f =>
    `<a href="${f.storage_path}">${f.filename}</a>`
  ).join('\n')

  return new Response(`<!DOCTYPE html><html><body>\n${links}\n</body></html>`, {
    headers: { 'Content-Type': 'text/html' }
  })
})
```

#### 5.3.2 客户端 pip 配置

在嵌入式 Python 目录中创建 `pip.ini`（Windows）：

```ini
[global]
index-url = http://<门户地址>/pypi/simple/
trusted-host = <门户地址>
```

Nginx 将 `/pypi/simple/` 和 `/pypi/packages/` 路由到 Supabase Edge Function 和 Storage。

可通过应用启动时动态生成此文件，地址从 Supabase 配置中获取。

#### 5.3.3 Agent 感知机制

**核心需求**：让 AI Agent 知道安装 Python 包时应走内网门户。

实现方式——在**系统提示词（System Prompt）**中注入规则：

```markdown
## Python 包管理规则

当前环境为内网，Python 包安装必须通过内网镜像源。
- 安装包命令：pip install <package>
- 已配置内网镜像源地址，pip install 会自动走内网
- 如果包安装失败，提示用户联系管理员将所需包上传到内网镜像源
- 禁止使用 --index-url 指向外部源
- 可用以下命令查看内网可用的包：pip list 或访问 http://<门户地址>/pypi/simple/
```

同时在 `.config/TOOLS.md` 或 `SOUL.md` 中添加此规则，确保所有 Agent 都能看到。

### 5.5 管理流程

```
管理员上传包的流程：

1. 管理员从公网下载 .whl 或 .tar.gz 文件
2. 登录 Web 门户后台，进入「Python 包管理」
3. 上传文件到 Supabase Storage（pypi-files 桶）
4. 系统自动解析包名、版本、依赖信息，写入 pypi_packages 表
5. 包立即可用，客户端 pip install 即可安装

Web 后台上传实现（前端调用）：

  // 1. 上传文件到 Storage
  await supabase.storage.from('pypi-files').upload(filename, file)

  // 2. 解析包信息后写入数据库
  await supabase.from('pypi_packages').insert({
    name, version, filename,
    storage_path: filename,
    file_size, file_hash, summary
  })
```

### 6.4 数据库设计

复用 Supabase Auth 的 `auth.users` 作为用户体系，通过 `profiles` 表扩展角色信息。

```sql
-- 用户档案表，扩展 auth.users
CREATE TABLE profiles (
  id            UUID REFERENCES auth.users ON DELETE CASCADE PRIMARY KEY,
  username      TEXT UNIQUE,
  role          TEXT DEFAULT 'user' CHECK (role IN ('user', 'admin')),
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- 新用户自动创建档案（触发器）
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO profiles (id, username) VALUES (NEW.id, NEW.email);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

-- Skill 表
CREATE TABLE skills (
  id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name          VARCHAR(256) NOT NULL,
  version       VARCHAR(64) NOT NULL,
  description   TEXT,
  emoji         VARCHAR(8),
  author        VARCHAR(128),
  keywords      TEXT[],
  mode          VARCHAR(16) DEFAULT 'on-demand',
  tags          TEXT[],
  storage_path  VARCHAR(512) NOT NULL,       -- Supabase Storage 中的 ZIP 路径
  file_size     BIGINT,
  file_hash     VARCHAR(128),
  status        VARCHAR(16) DEFAULT 'pending',
    -- pending → published / rejected / deprecated
  review_note   TEXT,
  submitted_by  UUID REFERENCES profiles(id),
  reviewed_by   UUID REFERENCES profiles(id),
  download_count INTEGER DEFAULT 0,
  rating_avg    DECIMAL(3,2) DEFAULT 0,
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  updated_at    TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(name, version)
);

-- Skill 评分表
CREATE TABLE skill_ratings (
  user_id       UUID REFERENCES profiles(id),
  skill_id      BIGINT REFERENCES skills(id) ON DELETE CASCADE,
  rating        SMALLINT CHECK (rating BETWEEN 1 AND 5),
  comment       TEXT,
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, skill_id)
);

-- 客户端已安装记录（可选，用于统计分析）
CREATE TABLE skill_installs (
  client_id     VARCHAR(128),
  skill_id      BIGINT REFERENCES skills(id),
  installed_version VARCHAR(64),
  installed_at  TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (client_id, skill_id)
);

-- RLS 策略
ALTER TABLE skills ENABLE ROW LEVEL SECURITY;
ALTER TABLE skill_ratings ENABLE ROW LEVEL SECURITY;

-- 已发布的 Skill 所有人可查看
CREATE POLICY "Published skills are public"
  ON skills FOR SELECT USING (status = 'published');

-- 登录用户可提交 Skill
CREATE POLICY "Authenticated users can submit"
  ON skills FOR INSERT
  WITH CHECK (auth.uid() = submitted_by);

-- 管理员可审核/管理
CREATE POLICY "Admins can manage skills"
  ON skills FOR UPDATE
  USING (auth.uid() IN (SELECT id FROM profiles WHERE role = 'admin'));

-- 评分：登录用户可写
CREATE POLICY "Users can rate"
  ON skill_ratings FOR INSERT
  WITH CHECK (auth.uid() = user_id);

-- 创建 Storage 桶
INSERT INTO storage.buckets (id, name, public)
VALUES ('skill-files', 'skill-files', true);
```

### 6.5 Supabase SDK 调用方式

```typescript
  .from('skills')
  .select('id, name, version, description, emoji, author, tags, download_count, rating_avg')
  .eq('status', 'published')
  .order('download_count', { ascending: false })

// 按标签搜索

  .from('skills')
  .select('*')
  .eq('status', 'published')
  .contains('tags', ['办公'])

// 提交 Skill（需登录）
await supabase.storage.from('skill-files').upload(zipPath, file)
await supabase.from('skills').insert({
  name, version, description, storage_path: zipPath,
  submitted_by: user.id, status: 'pending'
})

// 管理员审核
await supabase.from('skills')
  .update({ status: 'published', reviewed_by: adminId })
  .eq('id', skillId)

// 下载 Skill ZIP
const { data: url } = supabase.storage.from('skill-files').getPublicUrl(storagePath)

// 评分
await supabase.from('skill_ratings').insert({ user_id, skill_id, rating, comment })

// 递增下载计数
```

## 八、部署方案

### 8.1 部署架构（基于内网 Supabase）

Supabase 已部署在内网，只需额外部署 Web 前端和 Nginx：

```
内网服务器
├── Supabase（已部署）
│   ├── PostgreSQL       :5432      ← 数据库（已有）
│   ├── GoTrue (Auth)    :9999      ← 认证服务（已有）
│   ├── PostgREST        :3000      ← 自动 REST API（已有）
│   ├── Storage API      :5000      ← 文件存储（已有）
│   ├── Edge Runtime     :5555      ← Edge Functions（已有）
│   └── Realtime         :6000      ← 实时推送（已有）
│
├── Nginx                :80/:443   ← 统一入口（新增）
│
└── Web 门户静态文件                  ← 前端构建产物（新增）
    └── /var/www/portal/
```

**新增部署内容仅两部分**：
1. **Nginx**：统一反向代理，对外暴露单一入口
2. **Web 门户**：Vue 3 构建的静态站点，通过 Supabase JS SDK 访问后端

### 8.2 Nginx 路由规划

```nginx
server {
    listen 80;
    server_name portal.internal;

    # ── Web 门户（静态页面）──
    location / {
        root /var/www/portal;
        try_files $uri $uri/ /index.html;
    }

    # ── Supabase Auth ──
    location /auth/v1/ {
        proxy_pass http://supabase:9999/auth/v1/;
        proxy_set_header Host $host;
    }

    # ── Supabase REST API ──
    location /rest/v1/ {
        proxy_pass http://supabase:3000/rest/v1/;
        proxy_set_header Host $host;
    }

    # ── Supabase Storage ──
    location /storage/v1/ {
        proxy_pass http://supabase:5000/storage/v1/;
        proxy_set_header Host $host;
        client_max_body_size 500M;   # 允许大文件上传（安装包）
    }

    # ── Supabase Edge Functions ──
    location /functions/v1/ {
        proxy_pass http://supabase:5555/functions/v1/;
        proxy_set_header Host $host;
    }

    # ── Supabase Realtime ──
    location /realtime/v1/ {
        proxy_pass http://supabase:6000/realtime/v1/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # ── PyPI 镜像（路由到 Edge Function）──
    location /pypi/ {
        proxy_pass http://supabase:5555/functions/v1/;
        proxy_set_header Host $host;
    }
}
```

**客户端连接配置**：

```typescript
// 所有客户端使用统一的 Supabase 地址
const supabase = createClient(
  'http://portal.internal',      // Nginx 入口地址
  'eyJhbG...anon-key'            // Supabase anon key
)
// SDK 自动路由到 /rest/v1/、/storage/v1/、/auth/v1/ 等
```

### 8.3 HTTPS 配置（可选）

### 9.3 风险与对策

| 服务器宕机 | 所有服务不可用 | 数据库定期备份；考虑主备方案 |
| Skill 安全性 | 恶意脚本风险 | 人工审核 + 自动化安全扫描 |

| 客户端升级中断 | 升级失败导致不可用 | 升级前备份；失败自动回滚 |
